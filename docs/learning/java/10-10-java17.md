# Java 17 现代语法：record、sealed、文本块与模式匹配

优先级 P0（record/sealed/instanceof 模式必须掌握），目标层级 L3。前置：[类与多态](10-02-oop.md)、[String 与相等性](10-03-equality-and-strings.md)、[枚举](10-09-enum-datetime-bigdecimal.md)。项目基准 Java 17，这篇每个特性都标注了"哪个版本转正"，并全部实测过。

## 版本地图：先分清"正式"与"预览"

| 语法 | 正式版本 | Java 17 里能用吗 |
|------|---------|-----------------|
| `var` 局部变量推断 | Java 10 | 能 |
| 文本块 `"""` | Java 15 | 能 |
| `instanceof` 模式匹配 | Java 16 | 能 |
| `record` | Java 16 | 能 |
| `sealed` 密封类 | Java 17 | 能 |
| switch 模式匹配 | Java 21（17/18 只是预览） | **不能**（要 --enable-preview） |
| record 模式 | Java 21 | **不能** |

"预览（preview）"是 JDK 的机制：功能先以 `--enable-preview` 开关发布收集反馈，转正前语法和行为都可能变。生产代码不该开预览特性，所以判断"项目里能不能用"只看转正版本。这张表是春招的易错区：不少资料把 switch 模式匹配直接写进"Java 17 新特性"，是错的。

## record：一行顶一个类的不可变数据载体

### 问题的起点：数据类的样板成本

[类型与引用](10-01-types-and-references.md)到[相等性](10-03-equality-and-strings.md)反复出现同一种类：几个不可变字段 + 构造器 + 访问器 + 合规的 equals/hashCode + toString。手写全量 60 行起步，错一处 equals 就丢数据（HashMap 键失踪）。这种"纯数据载体"是如此常见，Java 16 给了它专用语法：

```java
public class RecDemo {
    record Point(int x, int y) {
    }

    public static void main(String[] args) {
        Point a = new Point(1, 2);
        Point b = new Point(1, 2);
        System.out.println(a);
        System.out.println(a.x());
        System.out.println(a.equals(b));
        System.out.println(a == b);
    }
}
```

```text
Point[x=1, y=2]
1
true
false
```

`record Point(int x, int y)` 一行声明，编译器自动生成：全参构造器、每个组件的访问器（**叫 `x()` 不是 `getX()`**，record 不遵循 JavaBean 命名）、合规的 `equals`（全部组件参与）、配对的 `hashCode`、`toString`。全部字段 `private final`，没有任何 setter——**record 天生不可变**，[String 与相等性](10-03-equality-and-strings.md)里"键必须不可变"的要求它天生满足：两个内容相同的 Point equals 为 true、hashCode 一致，能安全当 HashMap 键；而 `a == b` 仍是 false，record 不改变"new 出来的是不同对象"的引用语义。

record 的实现可以用 javap 直接验证（反编译字节码的工具，JDK 自带）：

```text
$ javap -p SealedDemo$Circle.class
Compiled from "SealedDemo.java"
final class SealedDemo$Circle extends java.lang.Record implements SealedDemo$Shape {
  private final double radius;
  SealedDemo$Circle(double);
  public final java.lang.String toString();
  public final int hashCode();
  public final boolean equals(java.lang.Object);
  public double radius();
}
```

（Circle 是下文 sealed 例子里声明的 record，这里提前看它的字节码。）`extends java.lang.Record`、字段全 final、方法全 final，构造器与组件一一对应。**没有 setter，也没有无参构造器**。

record 不只是哑数据，可以有方法（但不能有可变字段）。项目里现成的例子，`src/main/java/com/linkforge/link/service/ShortLinkService.java`：

```java
public record UnlockResult(ShortLink link, String cookieValue) {
    public boolean unlocked() {
        return cookieValue != null;
    }

    public boolean protectedLink() {
        return link != null && link.getAccessPasswordHash() != null;
    }
}
```

`unlocked()` 和 `protectedLink()` 是语义化查询：调用方（RedirectController）写 `result.unlocked()`、`result.protectedLink()` 而不是自己对着字段猜含义。"数据 + 围绕数据的派生判断"放一起，仍是不可变对象。

### record 和 Lombok @Data：两种选择并存是刻意的

项目里对外 JSON 的 DTO（如 `src/main/java/com/linkforge/link/dto/ShortLinkDetail.java`）用 Lombok `@Data`（可变、getter/setter、Jackson 反序列化生态友好），内部结果对象（`RateLimitDecision`、`RedirectOutcome` 的四个分支、`TargetPolicy.Verdict`、`UnlockResult`）全用 record（强制不可变）。**据代码推断**，这个分工的意图是：内部结果对象一旦构造就不该再被改（多处传递、并发读取都安全），外部 DTO 要配合序列化框架的传统约定。这是观察不是仓库声明，面试讲到这一层要如实说是推断。

还有一个真实的设计细节值得看，`src/main/java/com/linkforge/common/ratelimit/RateLimitDecision.java` 全文：

```java
/**
 * Outcome of one acquire against the sliding window log. {@code retryAfterSeconds} is
 * meaningful only when {@code allowed} is false.
 */
public record RateLimitDecision(boolean allowed, int retryAfterSeconds, long count) {
}
```

javadoc 明确写了"`retryAfterSeconds` 只在 allowed 为 false 时有意义"——record 没有"第二个字段为 null 才有效"的表达能力（它倾向全部字段有值），项目用**基本类型 + 文档约定**表达这种条件有效性（[包装类型](10-04-wrappers-and-boxing.md)分析过这个取舍）。record 也不是万能，条件有效性、大量可选字段时，普通类或 builder 仍占一席。

## sealed：把"有几种可能"锁死

### 问题的起点：多态的不完全处理

多态（[类与多态](10-02-oop.md)）让调用方无需知道具体类型，但**处理逻辑**（渲染响应、计算面积）终究要对每个子类型分支做不同的事。普通继承的隐患是子类型开放：任何人随时能 `extends` 出新子类，而你的 switch/if 链没管它，新增分支静默漏处理。sealed 的价值：**类型系统保证"子类型封闭"，编译器替你检查穷尽性**。

```java
public class SealedDemo {
    sealed interface Shape permits Circle, Square {
    }

    record Circle(double radius) implements Shape {
    }

    record Square(double side) implements Shape {
    }

    static double area(Shape s) {
        if (s instanceof Circle c) {
            return Math.PI * c.radius() * c.radius();
        }
        if (s instanceof Square q) {
            return q.side() * q.side();
        }
        throw new IllegalStateException("unknown shape " + s.getClass());
    }

    public static void main(String[] args) {
        System.out.println(area(new Circle(1)));
        System.out.println(area(new Square(3)));
    }
}
```

```text
3.141592653589793
9.0
```

`sealed interface Shape permits Circle, Square` 声明：Shape 的直接子类型**只有** Circle 和 Square，其他类 `implements Shape` 编译报错（`class is not allowed to extend sealed class: Shape (as it is not listed in its 'permits' clause)`）。permits 有一个省略规则，实测过：**不写 permits 时，与 sealed 声明在同一个编译单元（同一个文件）的子类型自动获得许可，嵌套在 sealed 声明体内的子类型也算；同包不同文件不算**。项目里 `RedirectOutcome` 的四个 record 直接嵌套在接口体内，走的就是默认许可，一个 permits 都不用写。

注意 area 里那个兜底 `throw new IllegalStateException`：它看起来多余（Shape 只有两种），存在的原因恰恰是**if 链没有穷尽检查**——编译器不会检查 if 链是否覆盖了所有子类型，兜底异常是手工补的保险。把 if 链换成 switch 就不一样了：

```java
static double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Square q -> q.side() * q.side();
    };
}
```

switch 对 sealed 类型做**穷尽检查**：两种子类型都覆盖了，连 default 都不用写；明天新增 `record Triangle implements Shape`，这处 switch 立即编译报错提醒你补分支。**漏分支从"静默运行期 bug"变成"编译错误"**，这是 sealed + switch 的全部价值所在。

但这套组合在 Java 17 用不了——switch 模式匹配当时还是预览特性。实测证据：

```text
$ javac --release 17 SwitchP.java
SwitchP.java:8: error: patterns in switch statements are not supported in -source 17
            case Circle c -> Math.PI * c.radius() * c.radius();
                 ^
  (use -source 21 or higher to enable patterns in switch statements)
```

同一份代码 `--release 21`（Java 21 正式支持）直接编译运行成功。我本机是 JDK 21 编译器，报错文案是"-source 17 不支持"；真在 JDK 17 上编译，报错会提示这是预览特性、需要 --enable-preview。**两种表述说的是同一件事：17 的正式语法没有 switch 模式**。

### 项目代码为什么用 if 链而不是 switch

`src/main/java/com/linkforge/link/controller/RedirectController.java` 的 render 方法处理四态判定，用的是 if-instanceof 链加兜底：

```java
private ResponseEntity<String> render(RedirectOutcome outcome, String code, boolean withBody) {
    if (outcome instanceof RedirectOutcome.Redirect redirect) {
        return ResponseEntity.status(HttpStatus.FOUND)
                .location(URI.create(redirect.url()))
                .build();
    }
    ...
    throw new IllegalStateException("unknown redirect outcome " + outcome.getClass());
}
```

**据代码推断**，在 Java 17 的正式语法下，if-instanceof 链是（当时）唯一不带预览开关的写法；若项目将来升到 Java 21，这段天然可以换成穷尽 switch 并删掉兜底 throw。这是"版本决定写法"的活案例。sealed 的收益在这里已经兑现了一半：`RedirectOutcome` 是 sealed interface（`src/main/java/com/linkforge/link/service/RedirectOutcome.java`），四个嵌套 record 是 `Redirect`（放行跳转）、`Blocked`（硬拦截 403）、`Locked`（密码锁）、`Warn`（警告页）——javadoc 明确写出了边界："404/410/429 留在异常通道"（D-Bw345-51 决策），**"门禁结果"走 sealed 多态、"硬错误"走 BizException**（[异常](10-06-exceptions.md)），两类出路的分工由类型系统表达。

### instanceof 模式匹配：判定与绑定一步

上面反复出现的 `s instanceof Circle c` 是 Java 16 正式的**模式匹配**：一步完成"是不是 Circle"的判定和"绑定到变量 c"。旧写法要判定、强转、赋值三步：

```java
if (o instanceof Circle) {
    Circle c = (Circle) o;
    c.radius();
}
```

新写法省掉强转，且 c 的作用域被编译器精确控制（只在判定成立的分支里可用）。项目里的真实用例，`GlobalExceptionHandler`：

```java
if (ex instanceof MethodArgumentNotValidException manv && manv.getBindingResult().getFieldError() != null) {
    msg = manv.getBindingResult().getFieldError().getDefaultMessage();
}
```

`instanceof X v` 之后可以直接用 v，包括同一行的 `&&` 右侧——绑定变量的作用域从模式成立处开始。

## 文本块：多行字符串的原文排版

HTML、SQL、JSON 这类多行字符串，传统写法是 `\n` 与 `+` 的拼接地狱。文本块（Java 15 正式）用三引号：

```java
public class TbDemo {
    public static void main(String[] args) {
        String page = """
                <html>
                  <body>hello</body>
                </html>
                """;
        System.out.println(page);
        System.out.println(page.length());
    }
}
```

```text
<html>
  <body>hello</body>
</html>

36
```

两条规则决定结果：** incidental（偶然）缩进被剥掉**——所有行共有的前导空白和结束引号的位置共同决定剥多少，这里内容行与结束 `"""` 对齐，共同缩进全部剥除，保留了 `<body>` 行相对多出的两个空格；**结尾换行算内容**——内容最后一行后面有一个换行符，所以长度是 36（6+1+20+1+7+1）而不是 35，打印后那个"空行"也是 println 追加的换行。想让内容不带结尾换行，把结束 `"""` 挪到内容行末尾即可。

项目里最合适的应用就是它，`src/main/java/com/linkforge/link/support/GatePages.java` 的三个门禁 HTML 页（拦截面、警告页、解锁页），配合 `.formatted(...)` 填充转义后的动态值：

```java
public static String warn(String targetUrl, String asciiHost, String code) {
    String safeUrl = HtmlUtils.htmlEscape(targetUrl);
    String safeHost = HtmlUtils.htmlEscape(asciiHost);
    String safeCode = HtmlUtils.htmlEscape(code);
    return """
            <!DOCTYPE html>
            ...
            <p>此短链将跳转到：<br><code>%s</code></p>
            ...
            """.formatted(safeUrl, safeHost, safeCode);
}
```

文本块负责"HTML 长什么样一目了然"，`formatted` 负责注入，`htmlEscape` 在注入前把动态值转义（防 XSS 的纪律：**先转义，再进模板**）。对比字符串拼接写法，可读性与可审安全性都更好——安全代码首先要能被人读懂。

## var：局部变量的类型推断

`var` 让编译器从右侧表达式推断局部变量类型，消除冗长但无信息的重复：

```java
var cache = new java.util.HashMap<String, java.util.List<com.linkforge.link.entity.ShortLink>>();
```

三条边界：**只用于局部变量**（字段、方法参数、返回类型不能用，因为那些是 API 表面，类型必须写明）；**推断后就是确定的类型**（var 不是动态类型，`var s = "a"; s = 1;` 编译错误，s 就是 String）；**该写类型时就写**（右侧是无参构造或方法调用看不出类型时，显式类型更可读）。var 是纯语法便利，与性能无关。项目各处的小型局部变量用了它，判断标准始终是"类型名是否冗长且显然"。

## 面试追问

**第一层：record 生成了什么，没生成什么？**
生成：全参构造器、组件访问器（x() 不是 getX()）、全组件 equals/hashCode/toString。没有：setter、无参构造器、可变字段。不可变由"字段全 final + 无写入口"保证。

**第二层：record 和 Lombok @Data 怎么选？**
record 强制深度不可变、契约由语言保证（equals/hashCode 编译器生成不会错）；@Data 可变、生态贴合传统 JavaBean（Jackson、JPA 的默认构造+setter 模式）。内部结果对象用 record，对外 DTO 常用 @Data——LinkForge 就是这个分工（据代码推断的意图：内部不可变保安全，外部兼容序列化生态）。

**第三层：sealed 解决什么问题？**
子类型封闭 + 编译期穷尽检查。配合 switch 模式，新增子类型时所有处理点编译报错，把"漏分支"从运行期 bug 提前到编译期。与枚举互补：枚举封闭"实例集合"，sealed 封闭"子类型集合"，后者允许每个子类型携带不同字段。

**第四层：switch 模式匹配是 Java 17 的特性吗？**
不是。17 里是预览（要 --enable-preview），Java 21 转正（JEP 441）；record 模式同样 21 转正。17 正式可用的是 instanceof 模式（16 转正）。这是高频版本陷阱题。

**第五层：LinkForge 的 RedirectController 为什么用 if 链不用 switch？**
（推断）sealed+switch 的穷尽检查需要 switch 模式匹配，17 正式语法没有；if-instanceof 链配一个兜底 throw 是 17 下的等效写法，升级 21 后可换穷尽 switch 并删兜底。面试答这类题的关键是先亮版本事实再谈取舍。

## 自测

1. `record Point(int x, int y)` 自动生成哪些成员？访问器名字是什么？
   答：构造器、x()/y()、全组件 equals/hashCode/toString；访问器无 get 前缀。
2. sealed 不写 permits 时子类型怎么获得许可？同包不同文件行不行？
   答：同编译单元（同文件）或嵌套在 sealed 声明体内自动许可；同包不同文件不行（实测拒绝）。
3. `instanceof Circle c` 比 `instanceof Circle` + 强转好在哪？
   答：一步完成判定与绑定，无显式强转，绑定变量作用域由编译器控制在模式成立的分支。
4. 文本块的 incidental indentation 指什么？
   答：所有内容行共有的前导空白（含结束引号位置参与计算）会被剥除，只保留相对缩进。
5. 为什么 RedirectOutcome 的四个分支是嵌套 record？
   答：嵌套走 sealed 默认许可（同声明体内），免写 permits；每态携带自己的字段（Redirect 带 url，Blocked 无字段），比枚举单例表达力强。
