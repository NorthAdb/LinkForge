# 类、封装、继承与多态

优先级 P0。前置：[类型与引用](10-01-types-and-references.md)。你现在已经知道"对象住在堆里，变量装着引用"，这篇讲对象是怎么被定义和组装出来的，以及 Java 靠什么机制让不同类型的对象能被统一处理。这是读懂 LinkForge 里每一个 Service、Controller、Entity 的前提。

## 从一个问题开始

写一个短链服务，每个链接要记录目标地址、点击数、状态。不用类，用变量和函数也能写：

```java
// 不用类的写法：一组平行的变量，人肉保持对应
String url1 = "https://example.com";
int clicks1 = 0;
int status1 = 1;

String url2 = "https://other.org";
int clicks2 = 0;
int status2 = 1;
```

麻烦立刻出现：`url1` 对应 `clicks1`、`status1`，这个"对应"只存在于你的脑子里。给 `clicks1` 加一之后想同步 `clicks2`，很容易手滑写成 `clicks3`。项目里有两万个链接时，这就是两万组平行的变量。而且"点击数不许为负""status 只能是 0 或 1"这类规则，要在每个碰这些变量的地方重复检查。

**类（class）解决的就是这个问题**：把一组数据和操作这些数据的代码装进一个模板，每个链接是这个模板的一个实例，数据和规则待在一起，编译器帮你看着。

## 类与对象：模板与实例

类定义了字段（每个对象一份的数据）和方法（所有对象共用、但操作"当前对象"的代码）。先看一个完整可运行的文件：

```java
class Link {
    String url;
    int clicks;
    int status;

    void recordClick() {
        this.clicks = this.clicks + 1;
    }
}

public class FirstObject {
    public static void main(String[] args) {
        Link link1 = new Link();
        Link link2 = new Link();
        link1.url = "https://example.com";
        link1.recordClick();
        System.out.println(link1.clicks);
        System.out.println(link2.clicks);
    }
}
```

```text
1
0
```

一个 Java 文件可以有多个顶层类，但最多一个 public，文件名必须与 public 类同名（这个文件叫 FirstObject.java）。示例为了自包含经常这样写，项目里的类则是一个文件一个 public 类。

`class Link` 定义了两样东西：

- **字段**（field）：`url`、`clicks`、`status`。每个 Link 对象都有自己的一份。
- **方法**（method）：`recordClick()`。所有 Link 对象**共用**同一份方法代码，但执行时操作的是"当前这个对象"的字段。

`new Link()` 创建一个对象：JVM 在堆上分配内存，按字段定义划出空间，全部填默认值（数字是 0，引用是 null，boolean 是 false），然后返回一个指向它的引用。

`link1` 和 `link2` 是两个独立对象（对照[类型与引用](10-01-types-and-references.md)里"一个对象多个引用"的例子，这里是"两个对象各自一份字段"）。`link1.recordClick()` 这个写法的含义是：调用 Link 类定义的 recordClick 方法，作用在 `link1` 指向的那个对象上。

方法体里的 `this` 就是"当前这个对象"的名字。`this.clicks` 表示"不是随便谁的 clicks，是这次调用作用在的那个对象的 clicks"。你可以不写 `this.`（没有歧义时编译器自动补上），但字段名和参数名撞车时必须写，下面的构造器会看到这种场合。

## 封装：把规则关进对象里

直接 `link1.clicks = -5;` 完全合法，因为字段没加任何限制。这样"点击数不为负"的规则就失守了。

**封装（encapsulation）**的做法：字段用 `private` 修饰，意思是只有本类的代码能碰它；对外提供方法作为唯一入口，规则写进方法：

```java
class Account {
    private long balance;

    long balance() {
        return balance;
    }

    void deposit(long amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("amount must be positive");
        }
        balance += amount;
    }
}

public class EncapFail {
    public static void main(String[] args) {
        Account acc = new Account();
        acc.balance = -100;
    }
}
```

```text
编译错误：
error: balance has private access in Account
```

`balance` 是 private 的，`balance()` 方法和 `deposit` 方法是公开的。试图绕过入口直接改字段，编译器拒绝。走 `deposit(-100)` 也进不来：异常检查会抛出 `IllegalArgumentException`，非法状态在两种路线上都被挡住。这就是封装的本质：**把"对象怎么才算对"这个知识锁在类内部，外部只能走被检查过的入口**。规则只有一处实现，改规则不用改所有调用方。字段全部 public 的类等于没有类，只是一堆变量的打包。

对外"读"用访问器（getter），"写"用修改器（setter），但 setter 不是必须的。LinkForge 的 `ShortLink` 实体（`src/main/java/com/linkforge/link/entity/ShortLink.java`）用 Lombok 的 `@Data` 注解自动生成全部 getter/setter，那是把样板代码交给工具生成，原理和你手写一样。而 `GatePages`（`src/main/java/com/linkforge/link/support/GatePages.java`）走另一个极端：一个 public 字段都没有，只暴露三个静态方法。按需暴露，不自动全开。

## 构造器：对象诞生时的检查

`new Link()` 能成功，是因为类没写构造器时编译器送了一个无参构造器。**构造器（constructor）**是对象创建时执行的特殊代码，名字与类名相同，没有返回类型。它最常见的用途是把"参数检查 + 字段初始化"集中在一处：

```java
class Link {
    private final String url;
    private int clicks;

    Link(String url) {
        if (url == null || !url.startsWith("http")) {
            throw new IllegalArgumentException("url must start with http");
        }
        this.url = url;
    }

    String url() {
        return url;
    }
}

public class CtorOk {
    public static void main(String[] args) {
        Link ok = new Link("https://example.com");
        System.out.println(ok.url().startsWith("https"));
    }
}
```

```text
true
```

构造失败的场合单独看：

```java
class Link {
    private final String url;

    Link(String url) {
        if (url == null || !url.startsWith("http")) {
            throw new IllegalArgumentException("url must start with http");
        }
        this.url = url;
    }
}

public class CtorFail {
    public static void main(String[] args) {
        Link bad = new Link("ftp://example.com");
    }
}
```

```text
运行异常：
java.lang.IllegalArgumentException: url must start with http
at Link.<init>(CtorFail.java:6)
at CtorFail.main(CtorFail.java:14)
```

几个新面孔：

- `private final String url`：`final` 让字段只能赋值一次，加上只能经构造器赋值，对象一旦建成 url 就不可能变。这是"不可变对象"的基本形态。
- `this.url = url`：参数名和字段名相同，`this.url` 指字段，右边的 `url` 指参数。不用 this 会变成自己赋值给自己，字段永远是默认值 null，这是真实的高频 Bug。
- 堆栈第一行是异常类型和消息。第二行 `at Link.<init>(CtorFail.java:6)` 指向构造器：`<init>` 是 JVM 对构造器的内部叫法。第三行是调用方位置。两行合起来读作："CtorFail 第 14 行 new Link，Link 第 6 行抛了异常"。
- `new Link("ftp://...")` 在构造器里抛了异常，**构造失败的对象不会存在**，变量 `bad` 从未被赋值。"不合法的对象根本建不出来"就是构造器检查的价值。

一个类可以有多个构造器，参数列表不同即可（这叫**重载**，overload）：

```java
Link(String url) { this(url, 0); }
Link(String url, int initClicks) { ... }
```

`this(url, 0)` 调用同一个类的另一个构造器，把公共逻辑收敛到一处。

## 继承：在已有类型上扩展

**继承（inheritance）**用 `extends` 表达"A 是一种 B"：

```java
public class Inherit {
    static class Animal {
        void speak() {
            System.out.println("some sound");
        }
    }

    static class Dog extends Animal {
        @Override
        void speak() {
            System.out.println("woof");
        }

        void fetch() {
            System.out.println("fetching");
        }
    }

    public static void main(String[] args) {
        Dog d = new Dog();
        d.speak();
        d.fetch();
    }
}
```

```text
woof
fetching
```

`Dog extends Animal` 的效果：Dog 对象里同时装着 Animal 的字段和 Dog 自己的字段；Animal 里非 private 的方法 Dog 自动拥有。`@Override` 标注"这个方法是重写父类里的同名方法"，它本身不做任何事，但**让编译器检查父类里真的存在签名相同的方法**。手滑写成 `void speak(string s)` 时，没有 `@Override` 编译器一声不吭地当作新方法，有 `@Override` 会直接报错。规则：**重写必标 `@Override`**。

子类构造器执行前，父类构造器先执行。如果父类构造器需要参数，子类要显式用 `super(...)` 调用。项目里现成的例子，`BizException`（`src/main/java/com/linkforge/common/exception/BizException.java`）：

```java
public class BizException extends RuntimeException {
    private final int code;

    public BizException(int code, String message) {
        super(message);
        this.code = code;
    }
}
```

`super(message)` 把 message 传给父类 RuntimeException 的构造器，父类把它存进自己私有的字段，`getMessage()` 才有东西可返回。`this.code = code` 存子类自己的字段。一句话：**super 管父类那部分，this 管本类这部分**。`RuntimeException` 是 Java 标准库里表示"运行时异常"的类，[异常](10-06-exceptions.md)篇专门讲它。

## 多态：同一个调用，不同的实现

现在看 Java 面向对象的核心机制。同样是 `speak()` 这个调用：

```java
public class Poly {
    static class Animal {
        void speak() {
            System.out.println("some sound");
        }
    }

    static class Dog extends Animal {
        @Override
        void speak() {
            System.out.println("woof");
        }
    }

    static class Cat extends Animal {
        @Override
        void speak() {
            System.out.println("meow");
        }
    }

    static void makeItSpeak(Animal a) {
        a.speak();
    }

    public static void main(String[] args) {
        makeItSpeak(new Dog());
        makeItSpeak(new Cat());
    }
}
```

```text
woof
meow
```

`makeItSpeak` 的参数类型是 Animal，收到的却是 Dog 和 Cat，而且两次调用执行了不同的方法体。这就是**多态（polymorphism）**：同一个调用形式，运行时按对象的真实类型执行对应的重写版本。

它的规则分两个时刻说，比"编译看左边，运行看右边"这句口诀更准确：

- **编译时**：编译器只看变量的声明类型（左边），检查"这个类型有没有 speak 方法"。有，放行；没有，编译错误。至于实际对象是什么，编译器不管。
- **运行时**：JVM 看引用实际指向的对象（右边），执行那个对象所属类里的重写版本。这叫**动态绑定**（dynamic binding）。

反过来，子类有而父类没有的方法，通过父类引用调不到：

```java
Animal a = new Dog();
a.fetch();
```

`fetch` 只在 Dog 里声明过，编译器按 `a` 的声明类型 Animal 找不到 fetch，直接编译错误，报 `cannot find symbol: method fetch()`。需要调用子类特有方法时，先判断真实类型再转换（`instanceof` 与模式匹配见 [Java 17 新语法](10-10-java17.md)）。

### 一个必须知道的例外：字段不参与多态

方法动态绑定，**字段却是按声明类型取的**：

```java
public class FieldHide {
    static class A {
        String tag = "A";
    }

    static class B extends A {
        String tag = "B";
    }

    public static void main(String[] args) {
        A obj = new B();
        System.out.println(obj.tag);
    }
}
```

```text
A
```

对象里其实有两份 tag（一份来自 A，一份来自 B），`obj.tag` 按声明类型 A 取到 "A"。这叫字段隐藏（hiding），是初学者最容易踩的反直觉点之一。实践结论：**不要在子类声明与父类同名的字段**，需要共享状态就继承同一个字段。知道这个例外是为了看懂别人的代码和应付追问，不是为了用。

## 抽象类与接口：两种"只定规矩不干全活"的类型

`makeItSpeak(new Animal())` 会让 Animal 自己的 speak 打印 "some sound"，可 Animal 是个抽象概念，发出"某种声音"毫无意义。**抽象类（abstract class）**禁止自己被实例化，允许留没有方法体的抽象方法强迫子类实现：

```java
public class AbstractDemo {
    abstract static class Animal {
        abstract void speak();

        void describe() {
            System.out.println("I am an animal");
        }
    }

    static class Dog extends Animal {
        @Override
        void speak() {
            System.out.println("woof");
        }
    }

    public static void main(String[] args) {
        Animal a = new Dog();
        a.speak();
        a.describe();
    }
}
```

```text
woof
I am an animal
```

`abstract void speak();` 没有方法体，子类必须重写，否则编译错误。`describe()` 是普通方法，子类直接继承。所以抽象类 = "部分实现的模板 + 一组必须由子类补齐的空缺"。

**接口（interface）**更纯粹，只声明"能做什么"，不管"怎么做的"：

```java
public class IfaceDemo {
    interface Formatter {
        String format(String input);
    }

    static class Upper implements Formatter {
        @Override
        public String format(String input) {
            return input.toUpperCase();
        }
    }

    static void printWith(Formatter f, String s) {
        System.out.println(f.format(s));
    }

    public static void main(String[] args) {
        printWith(new Upper(), "hello");
    }
}
```

```text
HELLO
```

`implements` 表示"我承诺实现这个接口的所有方法"。接口方法默认 public abstract。注意 `format` 前必须写 `public`：接口里方法隐含 public，实现时不能降低可见性，这是编译器强制的。

两者怎么选？看要不要**公共状态和部分实现**：

- 要把公共字段、模板方法留给子类用 → 抽象类。例：`InputStream` 系列的 read 逻辑骨架。
- 只定义能力契约、调用方完全不关心实现 → 接口。例：`Comparable`、项目里 MyBatis 的 Mapper 接口。
- Java 单继承（一个类只能 `extends` 一个父类），接口可以 `implements` 多个。接口不占继承名额，所以纯契约场景优先接口。

## static：属于类，不属于对象

普通字段每个对象一份，`static` 字段整个类共享一份；普通方法要作用在某个对象上，`static` 方法属于类，不经过对象就能调。本系列每个示例的 `main` 都是 static 方法，因为 JVM 启动时还没有任何对象。

你已经在[类型与引用](10-01-types-and-references.md)里见过项目里的真实用例：`TargetPolicy.Config.EMPTY` 是 static final 常量，全局唯一；`GatePages` 是"final 类 + private 构造器 + 全 static 方法"的工具类写法：

```java
public final class GatePages {
    private GatePages() {
    }

    public static String block() {
        ...
    }
}
```

`private GatePages()` 封死构造入口，`final` 封死继承入口，这个类永远不会被实例化或扩展，只是三个静态方法的命名空间。看到这种形态，直接读它的静态方法即可。

static 有一个必须警惕的坑：static 字段被**所有实例和所有线程共享**。往 static 集合里塞随请求变化的数据（比如"当前登录用户"），在并发下就是事故，原因见[并发](../13-concurrency.md)。

## 常见错误清单

| 错误 | 实际发生什么 | 修正 |
|------|-------------|------|
| 字段全 public，规则散落各处 | 任何代码都能造出非法状态 | private 字段 + 方法入口 |
| 构造器里 `url = url` | 参数赋给参数，字段还是 null | `this.url = url` |
| 重写方法不标 `@Override` | 拼错签名变成新方法，多态悄悄失效 | 一律标注，交给编译器检查 |
| 用继承只为复用父类代码 | "狗是一种动物"不成立的组合，行为错乱 | 组合：把工具类作为字段持有 |
| 期望字段也多态 | 字段按声明类型取（字段隐藏） | 子类不声明同名内段 |
| static 集合存请求级数据 | 多线程共享同一份，数据串号 | 实例字段或方法局部变量 |

"组合优于继承"值得一句展开：想复用 `Validator` 的逻辑，不一定继承它，把它作为字段 `private final Validator validator;` 持有并调用。继承表达"是一种"，组合表达"有一个"，拿错会写出 `LinkManager extends HashMap` 这种奇怪的继承树。

## LinkForge 里的真实代码

**三层异常继承链**。`RateLimitedException`（`src/main/java/com/linkforge/common/exception/RateLimitedException.java`）：

```java
@Getter
public class RateLimitedException extends BizException {
    private final int retryAfterSeconds;

    public RateLimitedException(int retryAfterSeconds) {
        super(429, "too many requests, retry later");
        this.retryAfterSeconds = retryAfterSeconds;
    }
}
```

链条是 `RateLimitedException extends BizException extends RuntimeException`。`super(429, "...")` 调的是 BizException 的双参构造器（重载的那一个），把 429 和消息交给父类。`@Getter` 是 Lombok 注解，编译期为 `retryAfterSeconds` 生成 getter，等价于手写 `public int getRetryAfterSeconds() { return retryAfterSeconds; }`。

多态在这里立刻兑现：`GlobalExceptionHandler`（`src/main/java/com/linkforge/common/exception/GlobalExceptionHandler.java`）里有两个处理方法，一个接 `RateLimitedException`，一个接 `BizException`。任何 BizException 子类抛出，都会被 BizException 的处理方法接住（参数类型是父类，子类对象传进来合法，这正是多态）；RateLimitedException 因为更具体，被更具体的方法优先接住并额外写入 Retry-After 响应头。哪些是框架行为要分清：**"子类对象可以传给父类类型参数"是 Java 语言的多态；"框架在两个处理方法里挑最具体的那个"是 Spring 的匹配规则**，不是语言保证。

**实体类即"数据 + 生命周期"**。`ShortLink` 实体类的字段就是数据库一行（id、code、originalUrl、status、expireAt...），MyBatis-Plus 注解（`@TableName`、`@TableId`）声明映射关系。它不写任何业务规则，规则全在 `ShortLinkService`。把"数据长什么样"（实体）和"数据怎么流动"（服务）分开，是业务代码的基本分工。

## 面试追问

**第一层：重载和重写的区别？**
重载（overload）是同一个类里方法名相同、参数列表不同的多个方法，编译期按调用处的参数类型挑选，与运行时对象无关；重写（override）是子类重新实现父类的同签名方法，运行期按对象真实类型动态绑定。重载不能只靠返回值区分，因为调用点没有上下文去消歧。

**第二层：动态绑定是怎么实现的？**
方法表（vtable 思路）。每个类有一张方法表，重写的方法在子类表里指向子类实现。调用 `a.speak()` 时 JVM 沿对象的真实类型查表分派。具体实现是 HotSpot 内部细节，语言层面只需知道"按运行时类型分派"。

**第三层：为什么 Java 要单继承、多接口？**
多继承带来钻石问题（两个父类有同一个方法，听谁的）。接口只承诺行为没有状态，冲突面小；Java 8 起接口允许 default 方法后，语言也规定同时实现多个接口的同一 default 方法时必须显式重写来解决冲突。这是"用规则消除歧义"的设计取舍。

**第四层：什么场景继承会出问题？**
父类实现变化破坏子类假设。典型：父类构造器调用可被重写的方法，子类重写版本在子类字段尚未初始化时执行，读到默认值。这类"脆弱基类"问题是组合优于继承的根源。LinkForge 的继承只用于两类安全场景：异常类型扩展（只加字段不改行为）和纯契约接口。

## 自测

1. `Animal a = new Dog(); a.speak();` 执行哪个 speak？如果 `Dog` 里还有 `fetch()`，`a.fetch()` 会怎样？
   答：执行 Dog 的 speak（动态绑定）；`a.fetch()` 编译错误，编译器只认声明类型 Animal 的方法。
2. private 字段被谁访问？封装的价值用一句话说？
   答：只有本类代码。"规则只有一处实现，外部只能走被检查的入口"。
3. `this` 和 `super` 在构造器里分别干什么？
   答：`this(...)` 调本类另一构造器，`super(...)` 调父类构造器，两者都必须是构造器第一行。
4. 抽象类和接口各举一个适用场景？
   答：抽象类：多个子类共享部分实现与状态；接口：纯能力契约，调用方不关心实现。
5. static 方法里能用 this 吗？
   答：不能。static 属于类，没有"当前对象"。
