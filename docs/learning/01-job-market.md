## 高频要求归纳（样本 + 通识，分三档）

**高频必备（样本反复出现 + 通识共识，P0）**：

1. Java 基础与集合（HashMap 原理是面经第一高频）。
2. 并发：线程池、synchronized/volatile、JUC 常用件。
3. JVM：内存区域、GC 基础、常见排查。
4. MySQL：索引（B+ 树/最左前缀）、事务与隔离级别、MVCC、慢 SQL。
5. Spring/Spring Boot：IoC/AOP/事务/自动配置/MVC 流程。
6. Redis：数据结构、缓存三问（穿透/击穿/雪崩）、一致性。
7. 消息队列：消息可靠性（丢失/重复/顺序）、幂等——样本 1 的 JD 明确点名「MQ 可靠性」，样本 5 的一面真题即「如何防止消息重复消费」。
8. 计算机网络：TCP/HTTP/HTTPS 基础。
9. 算法：手撕代码（高频中 med 题）。

**常见要求（多数岗位提及，P1）**：MyBatis（项目内 MP）、Spring Security/JWT、Linux 常用命令与排障、Git/Maven、Docker 基础、测试意识。样本 2 点名「性能调优」「高并发高可用」——对应限流/降级/演练话术。

**加分项（少数岗位，P2–P3，不为它打乱主线）**：Kafka/RocketMQ（会用 RabbitMQ 讲可靠性即可迁移）、ES、K8s、Spring Cloud 全家桶、虚拟线程/JDK 21（趋势但实习岗暂非门槛——样本 6 的营销口径需打折）、AI 应用后端。

**关键反指令**：不要因为某 JD 提到 K8s/ES/AI 就把它们抬进第一优先级；实习岗筛选的主力永远是基础 + 项目深度。

## 知识缺口分析（对照 LinkForge 与上述要求）

| 要求领域 | 项目覆盖 | 缺口与补法 |
|----------|----------|------------|
| Java/集合/并发/JVM | 直接覆盖（`SingleFlight` 等实例） | 项目外练习防「只会这个仓库」（[10-java-basics.md](10-java-basics.md) 及 java/ 系列） |
| MySQL | 索引/事务/排序规则真实案例 | EXPLAIN 亲手做、慢查询演练（[40-mysql.md](40-mysql.md)） |
| Spring | IoC/AOP/事务/MVC 全覆盖 | start.spring.io 独立搭一遍（防「项目依赖症」） |
| Redis | 缓存三问/滑窗/Bloom 全覆盖 | redis-cli 五结构（[50-redis.md](50-redis.md)） |
| MQ | RabbitMQ 可靠性全覆盖 | 管理台手工拓扑 + 幂等 demo（[51-rabbitmq-outbox.md](51-rabbitmq-outbox.md)） |
| 网络/OS | HTTP 语义有项目锚点 | 抓包与全流程口述（[20-network.md](20-network.md)） |

| 微服务治理 | 无 Spring Cloud（冻结） | 同上：单机机制 + 多实例边界表是差异化答案 |

## 与旧调研的增量修正

既有本地调研笔记（2026-10-24，基线 `main@0f4c3c3`）的结论在 v2.0.0 后需要更新三处：其标注「候选/缺口」的 Outbox、Bloom、singleflight、API Key、防钓鱼中间页、UV 口径**均已在代码落地**（A7–B9 波次）；「固定窗三入口」已升级为滑窗（B6）；bench 数字口径更新为带时期注（[82-linkforge-decisions.md](82-linkforge-decisions.md) 白名单）。面试话术按 v2.0.0 现状准备，旧表仅作历史参考。

## JD 关键词 → 项目话术映射（样本+通识）

投递前按目标岗位勾选：每行答案必须是「已有证据」或「诚实缺口」，禁止现场编造。

| JD 关键词 | 项目能指到的证据 | 话术要点 |
|-----------|------------------|----------|
| Java/Spring Boot | Boot 3.3.5 全套、Security、Validation、Actuator | 版本+规模（98 主类/48 测试类）开场 |
| MyBatis/ORM | MP 3.5.9、Wrapper、原生 SQL 两例 | SET NULL 坑与 Bloom 播种绕过逻辑删除是深挖点 |
| MySQL 索引/事务 | uk_code 兜底、同事务双写、V4 排序规则 | 「唯一索引=并发兜底」是差异化答案 |
| 缓存/Redis | 五层防线、双删、滑窗 Lua | 先答行是真相再答一致性窗口 |
| 缓存一致性 | 写穿+延迟双删、absent 语义 | 给窗口数字（1s/60s/10s） |
| 消息队列 | Outbox 全链、DLQ、drill | 断 MQ 演练实证是高潮 |
| 可靠性/幂等 | eventId 两态、唯一键去重 | at-least-once+幂等=效果等价 |
| 高并发 | 限流五入口、singleflight、缓存命中设计 | 禁止报未复测 QPS；报支配项分析 |
| 限流/熔断 | 滑窗+配额、fail-open/closed 矩阵 | 熔断组件没有→答 fail-open 承担最简熔断+组件候选 |
| 稳定性/排障 | drill 脚本、红史、时区故障 | 讲一个完整故障故事（F1） |
| 可观测 | Prometheus/Grafana、指标卫生、积压 gauge | 无界 tag 危害是考点 |
| 多租户 | 归属查询+404、TenantIsolationIT | 「根本查不到」vs「查到再判」 |
| 安全 | JWT/API Key/webhook 三件套、SSRF 清单 | 主动说 DNS rebinding 未防 |
| Docker/工程化 | Compose、CI、Testcontainers | 本机跑不了 IT 就说 CI 绿 |
| ES/分库/K8s | **缺口** | 「知道是什么、项目有意不做、要说清何时引入」 |

## 本档案的使用方式

- 选岗位后：按第 2 节三档清单自查，缺口回对应文档补。
- 投递前：对照 `LinkForge-jd-mapping.md` 第 4 节的投递检查清单（无注水、有故障故事、决策日志齐备）。
- 每月核对一次：春招临近时补 3–5 个目标公司最新 JD，更新本文样本表。

## 自测

1. 为什么算法线从第 1 周就开始？（答：它是独立于项目知识体系的最大缺口，每周 3 小时的复利积累无法冲刺期速成。）
2. 一份 JD 提到「熟悉 K8s」，你要不要立刻学？（答：先完成 P0 主线；K8s 对实习岗是加分项，面试讲「了解容器化、项目当前单机 Compose 形态，知道上 K8s 要补什么」即合格。）
3. 面试被问 Kafka 而你只用过 RabbitMQ，标准答法？（答：可靠性问题域相同（丢失/重复/顺序/积压），给出 RabbitMQ 的实战答案再类比 Kafka 的分区/offset 差异，承认未生产使用。）
4. 样本 9（PDD 提前批）对时间线的含义？（答：2027 届招聘节奏提前，简历在第 12 周就绪的里程碑不可顺延。）
